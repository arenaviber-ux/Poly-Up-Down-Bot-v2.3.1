## v2.3.1 — the two configuration defects

Both were reported by the bot's own `configWarnings()` but could not be fixed by
it. The reasoning is in `README.md` under **v2.3.1** and in `STRATEGIES.md`.

| File | What changed |
|---|---|
| `pricing.js` | New `entryEdgeTest()` — the single entry edge gate, tested at the executable price against `max(module gate, MIN_NET_EDGE)` |
| `strategyEngine.js` | `candidate()` uses it, so the engine no longer gates at the ask against a different threshold; signals now carry `executionPrice`, `edgeAtAsk` and `edgeLimitedBy` |
| `botCore.js` | `executeSignal()` uses the same function instead of re-deriving the edge, and records it on the position (`expectedEdge`, `edgeAtAsk`, `executionPrice`, `edgeLimitedBy`) |
| `config.js` | Module entry floors resolve against `MIN_SECONDS_TO_EXPIRY` at load (`resolveEntryFloors`); both warnings rewritten to say what is now true |
| `test/*.js` | All four runners fail on an unhandled rejection or uncaught exception — a crash after the summary used to exit 0 |
| `STRATEGIES.md`, `.env`, `.env.example` | The gate semantics, the resolved floor, and the `MIN_NET_EDGE` shadowing consequence, documented where you would look for them |

`MIN_SECONDS_TO_EXPIRY`, `MIN_NET_EDGE`, `SQS_MIN_EDGE` and `SQS_LAST_SECONDS`
**keep their shipped values** — the fix removes the inconsistency, it does not
quietly change your risk settings. If you want Stale-Quote Snipe to trade the 1¢
edge it was written for, lower `MIN_NET_EDGE` yourself.

## Behaviour you should expect to see differently

- A decided position is **sold** 10–45s before close instead of being held. The
  log says `[exit] SOLD …` with the price, shares and reason it sized that way.
- When the exit stands down, the log names the refusal code (`not-decided`,
  `depth-too-thin`, `bid-above-cap`, `too-late`, …). These are decisions, not
  errors.
- A win still settles. Positions are never deleted on exit — they carry
  `exitShares` / `exitProceedsUsd` / `remainingShares` and settle with
  `payout = exitProceedsUsd + (won ? remainingShares : 0)`.
- **A position you have fully sold no longer blocks `MAX_OPEN_POSITIONS`.**
  Before this change a settled-but-unredeemed win could keep the bot out of the
  market.
- In live mode, collateral is force-refreshed after a successful redemption, so
  the next order sees the money.
- Paper mode credits exits **once**, at settlement. It used to be possible to
  credit them twice; `exitStats.recycledUsd` is the paper recycling metric.

## Two things this does not do

1. **It is not a geoblock workaround.** The exit is a SELL through the same CLOB
   a BUY uses, and the sweeper goes through Polymarket's own Relayer. If your
   account cannot place orders it cannot place exit orders either. The shipped
   `.env` keeps `REQUIRE_GEOBLOCK_PASS=true`, and `AUDIT.md` records that
   Australia is close-only on both the frontend and the API.
2. **It does not make the sweeper work without credentials.** `AUTO_REDEEM`
   needs **Relayer** API Keys (`polymarket.com → Settings → API Keys → Relayer
   API Keys`) or Builder HMAC keys. Your existing `POLY_API_KEY` /
   `POLY_API_SECRET` / `POLY_API_PASSPHRASE` are CLOB L2 order-signing keys and
   cannot authorise a relayer transaction. Without them the sweeper reports
   itself not-ready with a reason, the pre-expiry exit keeps working, and
   nothing fails silently.

Also worth doing regardless: turn on the **account-level auto-redeem toggle** in
the Polymarket UI. It is not API-triggerable, but it is free and covers anything
this bot misses.
